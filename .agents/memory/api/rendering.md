# Zenith API: Graphics, Animation & VFX

Этот документ содержит полные технические спецификации графического движка, систем анимации и визуальных эффектов.

---

## 1. Animation System v2.0 (Quaternion Engine)
- **Dual-State ModelNode**: Гибридные узлы. Сохраняют старое поле `animRotation` (Euler) для 100% обратной совместимости и добавляют `animRotationQuat` (Quaternion) для новой системы. Вычисляются аддитивно.
- **Modular Additive Controller**: `ViewmodelController` парсит `version` из JSON. V1 треки пишутся напрямую в Euler, V2 треки конвертируются в `Quaternionf` и накладываются через сферическую интерполяцию (slerp).
- **Transition Buffer (Cross-fade)**: `ViewmodelController` делает "снимок" позы (`saveSnapshotRecursive`) при смене предметов и плавно сглаживает (lerp/slerp) предыдущий кадр с новым. Логика перенесена в конец кадра (после Инерции и Хвата).

---

## 2. Физика Viewmodel (Инерция и Хват)
- **Center-aligned Block Grip**: Блоки размещаются по центру `socket_palm` с использованием `flat_sheet` хвата (пальцы под блоком).
- **PCA Авто-ориентация**: `ItemMeshGenerator` использует метод главных компонент для анализа пикселей 2D-текстуры и автоматического вертикального разворота предмета.
- **Вес (Weight) и Инерция**: Поле `weight` в JSON предмета определяет силу пружинной физики 2-го порядка.
- **HeldItemRenderer**: Управляет трансформациями относительно костей кисти. Реализует динамическое прижатие блоков к ладони на основе их геометрии.

### 3. Visual Effects (VFX)

### 3.1. Unified Coloring System
- **Single Source of Truth**: Класс `ColorProvider` централизованно хранит цвета биома (трава, листва).
- **Smart Overlays**: Вместо проверки пикселей шейдер использует 4-ю текстурную координату (`OverlayLayer`) для наложения окрашиваемых масок поверх базовых текстур.
- **Cross-System Consistency**: Единые шейдеры для мира, viewmodel, инвентаря и частиц гарантируют идентичное отображение цветов.

### 3.2. Foliage Animation
- **JSON Property**: `"sway": true` включает анимацию для блока. По умолчанию `false`.
- **Vertex Weights**: Автоматическое назначение весов: `0.0` (корень) и `1.0` (верх). Для `DOUBLE_PLANT` веса `1.0` -> `2.0`.
- **Selection Sync**: Хитбокс автоматически следует за анимацией благодаря юниформе `uSwayOverride`.

### 3.3. Разрушение и Жар (Mining VFX)
- **Mining Heat VFX**: Накапливает **Heat (Жар)** при ударах. Инструмент или костяшки пальцев раскаляются (красная пульсация, маски Y и весов костей).
- **Persistent Scars**: Шрамы (зарубки) сохраняются в `Vector4f` (W - интенсивность). Плавно исчезают при регенерации блока (через 5 сек после удара).

### 3.4. Procedural Hand Conditions
Руки (Viewmodel) могут динамически покрываться процедурной кровью, грязью и влагой (`hand_conditions.glsl`).
- **Implementation**: Пятна накладываются пиксельно-точно поверх 3D-модели (Splatters) в зависимости от действий игрока.
- **Sway & Shake**: При падении добавляется высокочастотная тряска (45Hz), интенсивность которой зависит от вертикальной скорости.

## 4. Classic Voxel Particle System
- **Billboard Quads**: Плоские квадраты, ориентированные на камеру (GPU Billboarding).
- **Snippet UV Mapping**: Частица берет участок 4x4 пикселя из 16x16 текстуры блока.
- **No-Collision**: Частицы не имеют физических коллизий. Движутся по параболе и исчезают.
- **Context-Aware**: При ударе по Weak Spot частицы берут текстуру той грани, по которой нанесен удар.

## 5. Rendering Pipeline
- **Transparency/Translucency Pass Split**:
    - **Opaque Pass**: Отрисовка с `glDepthMask(true)`. Включает обычные блоки и блоки с флагом `transparent: true` (плиты, стадии дерева), которые не являются стеклом. Это гарантирует корректную запись в Z-буфер и перекрытие оверлеев.
    - **Translucent Pass**: Отрисовка с `glDepthMask(false)` и блендингом. Только для блоков с флагом `translucent: true` (стекло, вода).
- **MSAA 4x & Resolve**: Движок отрисовывает сцену в мультисэмпл-буфер для сглаживания краев.
- **Palette Corruption Guard**: `Chunk.getSnapshot` проверяет валидность индексов в палитре. При обнаружении выхода за границы ( corruption), индекс автоматически сбрасывается в `AIR` (0), а лог выводит предупреждение. Это предотвращает критические вылеты при чтении битых данных мира.
- **UTF-8 Stream**: Консольный вывод принудительно переведен на UTF-8 для корректного отображения кириллицы в именах предметов и логах на Windows.

## 6. Zero-Allocation Occlusion Culling
Высокопроизводительная система отсечения невидимой геометрии на основе графа связности мира.

### 6.1. 3D BFS Traversal
- **Connectivity Graph**: Мир представляется как граф узлов (секций 16x16x16). Каждый узел содержит 36-битную маску `visibilityMask`, описывающую возможность прохождения взгляда между любыми двумя гранями (6x6).
- **BFS Logic**: Алгоритм начинает обход с секции, где находится камера, и "растекается" по воздуху. Если текущая секция не пропускает взгляд от входной грани к выходной (например, глухой туннель), волна обхода в этом направлении останавливается.
- **Dynamic Updates**: Маска видимости пересчитывается асинхронно при любом изменении блоков в чанке. Граф видимости рендерера помечается грязным (`needsGraphRebuild`) только при физическом перемещении игрока между секциями или изменении маски.

### 6.2. Performance & Correctness
- **Strict Monotonicity**: Математическое ограничение векторов обхода. Волна может двигаться только "вперед" по осям X, Y, Z относительно игрока. Это устраняет "отражения" (Portal Leakage), когда взгляд мог вылететь в небо и вернуться на землю за спиной.
- **Zero-Allocation**: Весь цикл обхода ($O(N)$) реализован на примитивных массивах. Использование `visitedFast` (short array с ID визита) позволяет сбрасывать состояние посещенных узлов за $O(1)$ без очистки массива.
- **Front-to-Back Opaque Sorting**: Все видимые непрозрачные секции сортируются по дистанции (`distanceSquared`). Это позволяет GPU Radeon использовать Early-Z для мгновенного отбрасывания пикселей, скрытых за ближайшей геометрией, экономя филлрейт.

## 8. Minimap & Radar System
Система тактического радара объединяет динамическое сэмплирование мира и процедурную графику.

- **Fast Voxel Sampling**: Метод `world.getFastSurfaceColor(x, z)` напрямую читает `blockData` чанка, находя верхний твердый блок за 1 проход по вертикали.
- **Dynamic Texture Update**: Использование `glTexSubImage2D` для обновления 128x128 текстуры без пересоздания объекта.
- **SDF Shader effects**: Шейдер `minimap_fragment.glsl` применяет круговую маску, виньетирование и динамические сканирующие линии (Scanlines).
- **Radar Sonar logic**: При наличии шума (`uNoiseLevel > 0`) в шейдере вычисляется динамическое кольцо `fract(uTime * 1.5)` с максимальным радиусом `uNoiseLevel * 0.45`. Это визуализирует зону слышимости игрока мобами.
- **Player-Centric Rotation**: Рендерер вращает меш карты в обратную сторону от `player.yaw`, сохраняя направление взгляда игрока всегда "вверх" по карте.
- **Marker Rotation**: Позиции сущностей (мобов, предметов) трансформируются той же матрицей вращения для корректного отображения на радаре.

## 9. Mathemagical Weather & Realistic Wetness
Комплексная система погодных условий и процедурных эффектов намокания.

### 9.1. Spatiotemporal Synchronization & Block Occlusion
Использует технологию **Mathemagical Sync** для идеального совпадения капель в воздухе и брызг на земле без обмена данными:
- **Global Grid**: Весь мир разбит на детерминированную сетку $0.5 \times 0.5$ метра.
- **Unified Formula**: И падающие капли (`rain_vertex.glsl`), и поверхность земли (`fragment.glsl`) вычисляют время и место удара по идентичной формуле на основе мировых координат сетки и `uTime`.
- **GPU-Driven Block Occlusion**: Для предотвращения падения дождя сквозь твердые блоки (навесы, пещеры) используется легковесная текстура карты высот $64 \times 64$ вокруг камеры. Она заполняется на CPU из предрассчитанных воксельных данных высот чанков ($O(1)$) и сэмплируется в вершинном шейдере `rain_vertex.glsl`. Если высота полета капли становится меньше высоты блока, ее вершины схлопываются, отсекая примитив с нулевыми затратами на растеризацию.
- **Zero-Allocation**: Система работает полностью на GPU, не создавая нагрузки на CPU и GC.

### 9.2. Procedural Wetness Effects (fragment.glsl)
- **Ripples (Круги)**: На верхних гранях (`Y > 0.5`) рисуются расширяющиеся кольца. Каждый блок имеет уникальный паттерн на основе `vBlockPos`.
- **Impact Splashes (Всплески)**: В момент детерминированного удара капли рисуется вертикальный белый всплеск (процедурная игла).
- **Flowing Droplets (Потеки)**: На боковых гранях стен рисуются стекающие капли через скроллинг шума.
- **Wet Specular (Блики)**: Блоки приобретают глянцевость (Blinn-Phong). Интенсивность настраивается в JSON блока: `"wetnessFactor": 0.0` (пористые, только темнеют) до `1.0` (глянцевые, сильный блик).

### 9.3. Weather Manager (DDD)
- **States**: `CLEAR`, `RAIN`, `STORM`.
- **Configuration**: Шансы (`weight`), интервалы проверок и скорость перехода (`transitionDuration`) настраиваются в `world.json`.
- **Atmospheric Dimming & Cinematic Clear-Up**: `AtmosphereManager` автоматически приглушает свет солнца и неба и увеличивает плотность тумана (haze) при дожде. После дождя запускается кинематографичное прояснение: туман плавно рассеивается на 98% за ~8 секунд, а затем медленно возвращается к базовому состоянию за ~125 секунд.
- **Fog-Free Clouds**: Рендеринг облаков в `CloudRenderSystem.java` выполняется с отключенной записью глубины (`glDepthMask(false)`), что полностью исключает облака из пост-процессингового тумана и сохраняет их естественную контрастную окраску.
