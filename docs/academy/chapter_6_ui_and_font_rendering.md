# Глава 6. Рендеринг интерфейсов & Шейдерная анимация шрифтов

В этой главе мы изучим устройство UI-системы движка Zenith v4. Мы разберем, как верстать адаптивные интерфейсы с помощью JSON, как управлять буфером отрисовки с помощью трафаретных масок OpenGL и как превратить обычный текст в живую шейдерную анимацию.

---

## 1. Декларативная JSON-верстка GUI

В старых графических движках координаты каждого элемента интерфейса (кнопок, слотов, иконок) прописывают прямо в коде:
`drawSlot(x + 120, y + 45);`
Это приводит к тому, что при изменении разрешения экрана или масштаба интерфейса элементы расползаются, накладываются друг на друга и ломают UI.

В Zenith v4 GUI верстается **декларативно в JSON-файлах** (папка `gui/`). В Java-коде мы пишем только логику-контроллер, а всю математику позиционирования берет на себя движок.

```
       JSON Макет                  GUIConfig Layout              Финальный Экран
  ┌──────────────────┐          ┌──────────────────────┐       ┌─────────────────┐
  │ "slots": 9,      │   ───>   │  Relative Anchors    │ ───>  │  [■][■][■][■]   │
  │ "anchor": "center"│         │  "slots" units calc  │       │  [■][■][■][■]   │
  └──────────────────┘          └──────────────────────┘       └─────────────────┘
```

### 1.1 Ключевые концепции разметки
*   **Единицы измерения `"slots"` (символ `"s"`)**: Вместо жестких пикселей координаты задаются в размерах ячеек инвентаря. `"x": "3s"` означает: сместить элемент на расстояние 3 слотов с учетом стандартных зазоров (spacing) между ними.
*   **Относительные якоря (`relativeTo`)**: Элементы связываются друг с другом. Группа слотов брони может иметь якорь на левую грань сетки инвентаря. Если сетка инвентаря сдвинется, броня послушно сдвинется за ней, сохраняя идеальный отступ.
*   **Адаптивные фоны (`includeGroups`)**: Задний фон окна (размытая стеклянная панель) не имеет жесткого размера. Движок сканирует все активные группы элементов, вычисляет их общий охватывающий прямоугольник (Bounding Box) и автоматически растягивает красивую панель ровно под этот размер.

## 2. Аппаратное отсечение пикселей через `glScissor`

Когда мы делаем прокручиваемый список статей в Дневнике Выжившего (`Survivor's Tablet`), текст и иконки при прокрутке вверх или вниз должны красиво исчезать на границах панели, а не вылезать на поля книги.

Для этого используется аппаратный тест отсечения OpenGL — **Scissor Test**.

```java
GL11.glEnable(GL11.GL_SCISSOR_TEST); // Включаем тест
GL11.glScissor(x, y, width, height);  // Задаем прямоугольник отсечения
// ... Отрисовка списка ...
GL11.glDisable(GL11.GL_SCISSOR_TEST); // Выключаем
```
Любой пиксель, который рендерер попытается нарисовать за пределами прямоугольника `glScissor`, будет аппаратно проигнорирован видеокартой на стадии растеризации.

### 2.1 Магия инверсии координаты Y
> [!CAUTION]
> **Критическая ловушка для новичков!**
> Координатная сетка нашего UI считает началом координат $(0,0)$ **левый верхний угол** экрана, а ось Y направлена **вниз** (стандарт для 2D-графики).
> Однако координатная сетка `glScissor` в OpenGL считает началом координат $(0,0)$ **левый нижний угол** физического окна, а ось Y направлена **вверх** (стандарт для 3D-математики).

```
   UI Координаты (Y-Down)                   OpenGL Scissor (Y-Up)
   (0,0) ──────────────────┐                 ┌──────────────────┐ (width, height)
    │                      │                 │  glScissor Box   │
    │   ┌──────────────┐   │                 │   ┌──────────┐   │
    │   │ UI Panel     │   │                 │   │          │   │
    ▼   └──────────────┘   │                 │   └──────────┘   │
                           │                 (0,0) ─────────────┘
```

Если передать координаты панели UI напрямую в `glScissor`, зона отсечения окажется перевернутой "вверх ногами" и обрежет совсем не те элементы.

В `ScrollPanel.java` мы выполняем математическое преобразование координат с учетом текущей высоты окна игрока `windowHeight`:
```java
// Перевод Y UI-координат в Y-координаты OpenGL Scissor
int scissorX = Math.round(uiPanelX * scaleFactor);
int scissorWidth = Math.round(uiPanelWidth * scaleFactor);
int scissorHeight = Math.round(uiPanelHeight * scaleFactor);

// Инвертируем Y: берем высоту окна, вычитаем Y-координату панели и её высоту
int scissorY = Math.round((windowHeight - (uiPanelY + uiPanelHeight)) * scaleFactor);

GL11.glScissor(scissorX, scissorY, scissorWidth, scissorHeight);
```
Параметр `scaleFactor` учитывает DPI монитора (например, на Retina или 4K экранах физическое разрешение окна в пикселях в 2 раза больше виртуального).

## 3. Отрисовка шрифтов & Управляющие коды

Вывод текста на экран в низкоуровневой графике — сложная задача. Мы не можем просто отправить строку в GPU.
1.  **Character Atlas (Атлас символов)**: Движок генерирует большую текстуру, содержащую все буквы алфавита (латиницу, кириллицу, цифры и знаки).
2.  **Генерация меша**: Для каждой буквы в строке `FontRenderer` генерирует плоский прямоугольник (Quad) из 4 вершин, настраивая текстурные координаты UV так, чтобы они указывали точно на область этой буквы в атласе.
3.  Все квадры букв упаковываются в один буфер и рисуются за один Draw Call.

### Minecraft-style управляющие коды
`FontRenderer` парсит строки на наличие символа `$`.
*   `$0` - `$f` — переключают цвета (стандартная палитра).
*   `$l` — включает жирный шрифт (делает смещение вершин букв по X, рисуя их дважды с микро-шагом).
*   `$o` — включает курсив (применяет шейдерный скос матрицы модели вбок).
*   `$r` — сбрасывает все эффекты.

## 4. Живые шейдерные эффекты текста в `ui_fragment.glsl`

Zenith v4 выводит визуализацию текста на новый уровень. Мы передаем в шейдер `ui_fragment.glsl` специальные флаги анимаций. Давай разберем их математику.

```glsl
// ui_fragment.glsl
in vec2 vTexCoords;
in vec4 vColor;
in vec2 vLocalPos; // Координаты внутри текста
uniform float uTime;
uniform uint uTextEffects; // Битовая маска эффектов

out vec4 FragColor;
```

### 4.1 Эффект Радуги (`$z` — Rainbow)
Цвет букв плавно переливается всеми цветами радуги. Мы вычисляем сдвиг цветового тона (Hue) на основе координаты X буквы и системного времени:
```glsl
if ((uTextEffects & EFFECT_RAINBOW) != 0u) {
    // Вычисляем угол на цветовом колесе (0.0 - 1.0)
    float hue = fract(uTime * 0.2 + vLocalPos.x * 0.005);
    
    // Переводим HSV в RGB
    vec3 rgb = hsv2rgb(vec3(hue, 0.8, 1.0));
    FragColor = vec4(rgb, 1.0) * texture(uTexture, vTexCoords);
}
```

### 4.2 Эффект Волны (`$v` — Wave)
Буквы плавно плывут вверх-вниз по синусоидальной волне. Этот расчет происходит в **вершинном шейдере** `ui_vertex.glsl`:
```glsl
if ((uTextEffects & EFFECT_WAVE) != 0u) {
    // Сдвигаем Y координату вершины по синусоиде
    float waveOffset = sin(uTime * 4.0 + aLocalPos.x * 0.05) * 4.0; // Амплитуда 4 пикселя
    finalPosition.y += waveOffset;
}
```

### 4.3 Эффект Тряски (`$q` — Shake)
Буквы мелко и хаотично вибрируют, создавая эффект страха или нестабильности (используется при критической прочности оружия):
```glsl
if ((uTextEffects & EFFECT_SHAKE) != 0u) {
    // Генерация псевдослучайного шума на основе времени
    float shakeX = sin(uTime * 50.0 + aLocalPos.y) * 0.8;
    float shakeY = cos(uTime * 45.0 + aLocalPos.x) * 0.8;
    finalPosition.xy += vec2(shakeX, shakeY);
}
```

## 5. Подготовка к собеседованию (IT-Шпаргалка)

### Вопрос 1: Как работает scissor-тест (`glScissor`) в OpenGL? Чем он отличается от настройки области вывода `glViewport`?
*   **Ответ**: 
    *   **`glScissor`** задает прямоугольную область отсечения на экране. После растеризации фрагментов видеокарта проверяет их координаты. Любые пиксели, выходящие за пределы рамки scissor-теста, аппаратно отбрасываются. Отрисовка за пределами рамки не происходит.
    *   **`glViewport`** определяет область трансформации координат. Он берет Normalized Device Coordinates (от -1.0 до 1.0) и масштабирует их в пиксели указанной области экрана. Если вы уменьшите `glViewport`, вся ваша сцена сожмется и отрендерится внутри этой маленькой области.
    *   *Кратко*: `glViewport` сжимает/масштабирует картинку под размер рамки, а `glScissor` работает как трафарет — он обрезает края картинки без изменения её масштаба.

### Вопрос 2: В чем заключается сложность синхронизации Y-координат при использовании `glScissor` в графических интерфейсах? Как её решить?
*   **Ответ**: Сложность в несовпадении точек начала координат (осей Y) в 2D UI-системах и низкоуровневом OpenGL:
    *   В UI точка $(0,0)$ находится в **левом верхнем углу** экрана, ось Y направлена **вниз**.
    *   В `glScissor` точка $(0,0)$ находится в **левом нижнем углу** окна, ось Y направлена **вверх**.
    *   Для решения этой проблемы необходимо пересчитывать координату $Y_{scissor}$ по формуле инверсии:
        $$Y_{scissor} = (WindowHeight - (UI\_Y + UI\_Height)) \times ScaleFactor$$
        Параметр $ScaleFactor$ (масштаб экрана) обязателен для корректного учета Retina/4K дисплеев с высоким DPI, где реальный буфер пикселей окна больше виртуальных координат UI.

### Вопрос 3: Как реализовать шейдерный эффект «перелива радуги» (Rainbow text) для отдельных букв текста?
*   **Ответ**: 
    1.  При генерации меша строки для каждой вершины буквы мы записываем её локальную горизонтальную координату `aLocalPos.x` (смещение буквы от начала строки).
    2.  Передаем эту координату во фрагментный шейдер как интерполируемый параметр `in vec2 vLocalPos;`.
    3.  Во фрагментном шейдере вычисляем цветовой тон *Hue* в диапазоне от 0.0 до 1.0, смещая его по времени и координате:
        $$\text{hue} = \text{fract}(uTime \times Speed + vLocalPos.x \times Frequency)$$
    4.  Переводим цвет из пространства HSV (где насыщенность $S=0.8$, яркость $V=1.0$, а тон $H=\text{hue}$) в пространство RGB с помощью стандартной функции преобразования:
        ```glsl
        vec3 hsv2rgb(vec3 c) {
            vec4 K = vec4(1.0, 2.0 / 3.0, 1.0 / 3.0, 3.0);
            vec3 p = abs(fract(c.xxx + K.xyz) * 6.0 - K.www);
            return c.z * mix(K.xxx, clamp(p - K.xxx, 0.0, 1.0), c.y);
        }
        ```
    5.  Умножаем полученный RGB-цвет на пиксель из текстурного атласа шрифта.
