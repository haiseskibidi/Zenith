## 1. Процедурная физика рук (2nd-Order Spring System)

Когда игрок движется или вращает головой, его руки и предметы в руках отстают и колеблются с приятной инерцией. Вместо того чтобы рисовать сотни статичных анимаций для каждого чиха, в Zenith используется **динамический симулятор физики пружины 2-го порядка (пружина-масса-демпфер)**.

```
       ┌────────────────────────┐
       │   Камера (Целевая)     │
       └──────────┬─────────────┘
                  │  (Виртуальная пружина: Жесткость k)
                  ▼
              (  / \  )   <-- Демпфер (Трение c) гасит колебания
              ( \ / / )
                  ▼
       ┌────────────────────────┐
       │   Рука (Масса m)       │
       └────────────────────────┘
```

### 1.1 Дифференциальное уравнение пружины
Физическое поведение системы описывается дифференциальным уравнением второго порядка:
$$m \frac{d^2x}{dt^2} + c \frac{dx}{dt} + k(x - x_{target}) = 0$$

Где:
*   $x$ — текущая позиция руки.
*   $x_{target}$ — целевая позиция (куда должна прийти рука вслед за взглядом).
*   $m$ — **Mass (Масса)**. Определяет инерцию. Чем тяжелее предмет, тем дольше он ускоряется и дольше останавливается.
*   $c$ — **Damping (Демпфирование/Трение)**. Сила, гасящая колебания. Без нее пружина качалась бы вечно.
*   $k$ — **Stiffness (Жесткость пружины)**. Сила, стремящаяся вернуть руку к центру.

### 1.2 Численное интегрирование в Java
Чтобы решить это уравнение на каждом кадре в Java, мы используем схему **Semi-implicit Euler integration** (полунеявный метод Эйлера), так как он невероятно быстрый и стабильный:

```java
// com.za.zenith.engine.graphics.model.ViewmodelPhysics.java
public class ViewmodelPhysics {
    public float currentX = 0f;
    public float velocityX = 0f;
    
    public float mass = 1.0f;     // Тяжесть предмета
    public float damping = 8.0f;   // Сопротивление
    public float stiffness = 50.0f;// Жесткость пружины

    public void update(float targetX, float deltaTime) {
        // 1. Жесткое ограничение deltaTime для защиты от взрыва физики при фризах FPS
        float dt = Math.min(deltaTime, 0.05f);
        
        // 2. Расчет силы пружины (Закон Гука) и силы трения
        float springForce = (targetX - currentX) * stiffness;
        float dampingForce = -velocityX * damping;
        
        // 3. Вычисление ускорения (Второй закон Ньютона: F = m*a -> a = F/m)
        float accelerationX = (springForce + dampingForce) / mass;
        
        // 4. Интегрирование скорости и позиции
        velocityX += accelerationX * dt;
        currentX += velocityX * dt;
        
        // 5. Защита от NaN/бесконечности
        if (!Float.isFinite(currentX)) {
            currentX = targetX;
            velocityX = 0f;
        }
    }
}
```
**Эффект Game Feel**: У деревянного топора `mass = 1.0`, он быстро следует за взглядом. Но когда вы берете в руки тяжелую наковальню, движок динамически считывает `"weight": 3.5` из JSON, увеличивая `mass` пружины. Руки начинают приятно "отваливаться" вниз, отставать при резких поворотах и медленно догонять центр экрана, создавая ощущение огромной физической массы объекта.

## 2. Кватернионы (3D Вращения & Сглаживание)

Классический подход к описанию поворота объекта в 3D — это три угла Эйлера: **Pitch (Тангаж / наклон вверх-вниз)**, **Yaw (Рыскание / поворот влево-вправо)** и **Roll (Крен / завал на бок)**.

### 2.1 Проблема Gimbal Lock (Шарнирный замок)
При использовании углов Эйлера поворот рассчитывается последовательным перемножением матриц вращения вокруг трех локальных осей.
Если объект наклонить по Pitch на 90 градусов вверх, локальная ось Roll совпадет с глобальной осью Yaw. Объект теряет одну степень свободы! Поворот вокруг одной оси начинает дублировать другую, вызывая критический баг — **Gimbal Lock (Шарнирный замок)**, из-за которого 3D-модели рук начинают хаотично вращаться и дергаться.

```
       ┌────────────────────────────────────────────────────────┐
       │                  GIMBAL LOCK                           │
       │                                                        │
       │        Ось X (Pitch) наклонена на 90°                  │
       │        Ось Y (Yaw) и Ось Z (Roll) совпали!             │
       │        Потеряна 3-я плоскость вращения.                │
       └────────────────────────────────────────────────────────┘
```

### 2.2 Решение: Кватернионы (`Quaternionf`)
Кватернион — это математический объект, расширяющий комплексные числа, с четырьмя компонентами: $q = (x, y, z, w)$.
В 3D графике кватернион представляет собой поворот вокруг произвольного единичного вектора (оси) $\vec{u}$ на угол $\theta$:
$$q = \left( u_x \sin\frac{\theta}{2},\ u_y \sin\frac{\theta}{2},\ u_z \sin\frac{\theta}{2},\ \cos\frac{\theta}{2} \right)$$

**Преимущества кватернионов**:
1.  **Нет Gimbal Lock**: Вращение происходит сразу в четырехмерном пространстве, оси никогда не схлопываются.
2.  **Идеальное сглаживание (Slerp)**: Если нам нужно плавно переключить анимацию рук со стойки покоя на удар, кватернионы позволяют делать сферическую линейную интерполяцию — **Slerp (Spherical Linear Interpolation)**.

```java
// Сферическое сглаживание между двумя позами костей в Zenith v2.0
public static Quaternionf slerp(Quaternionf start, Quaternionf end, float alpha, Quaternionf dest) {
    return start.slerp(end, alpha, dest); // Кратчайшая дуга на сфере 3D поворотов!
}
```
В отличие от углов Эйлера, которые при интерполяции крутят объект по уродливым ломаным траекториям, Slerp поворачивает кость по идеальной, кратчайшей дуге на сфере вращений.

## 3. Математика PCA (Principal Component Analysis) для текстур

Когда вы берете в руки плоский предмет (кирку), движок строит его 3D воксельный меш из 2D текстуры. Но как узнать, под каким углом правильно повернуть этот меш, чтобы он лег в ладони естественно, а не торчал боком?

В `ItemMeshGenerator` мы применили **метод главных компонент (PCA)** — классический алгоритм линейной алгебры и машинного обучения!

```
     Текстура предмета          Облако пикселей            Главные Оси (PCA)
     ┌──────────────┐          ┌──────────────┐          ┌──────────────┐
     │   /          │          │   *          │          │   / e1       │
     │  / Кирка     │   ───>   │  * *  *      │   ───>   │  /           │
     │ /            │          │ *   *        │          │ / ────> e2   │
     └──────────────┘          └──────────────┘          └──────────────┘
                                                          e1 - Длина рукояти
```

### 3.1 Алгоритм PCA на пикселях
1.  **Сбор данных**: Движок сканирует 2D-картинку 16x16. Для каждого непрозрачного пикселя мы получаем координаты $(x_i, y_i)$.
2.  **Центрирование**: Вычисляем средние координаты (центр масс предмета) $\bar{x}, \bar{y}$ и сдвигаем облако точек в начало координат:
    $$x'_i = x_i - \bar{x},\quad y'_i = y_i - \bar{y}$$
3.  **Ковариационная матрица**: Строим матрицу ковариации размером 2x2. Она показывает, насколько координаты X и Y зависят друг от друга (вытянутость текстуры):
    $$\Sigma = \begin{bmatrix} 
    \text{Cov}(X,X) & \text{Cov}(X,Y) \\ 
    \text{Cov}(Y,X) & \text{Cov}(Y,Y) 
    \end{bmatrix}$$
4.  **Нахождение Собственных Векторов**: Мы решаем характеристическое уравнение матрицы, чтобы найти ее **собственные векторы $\vec{e}_1, \vec{e}_2$ (eigenvectors)** и **собственные значения $\lambda_1, \lambda_2$ (eigenvalues)**:
    $$\Sigma \vec{e} = \lambda \vec{e}$$
    *   Собственный вектор $\vec{e}_1$, соответствующий наибольшему значению $\lambda_1$, указывает направление наибольшего разброса точек. **Это и есть физическое направление рукоятки предмета!**
5.  **Авто-ориентация**: Движок вычисляет угол наклона вектора $\vec{e}_1$ относительно вертикали и автоматически поворачивает весь 3D-меш предмета, выпрямляя его.
6.  **Smart Grasping**: Мы находим крайние пиксели вдоль главной оси и совмещаем их с суставом кисти игрока. Рукоятка топора идеально ложится в руку!

## 4. Скелетный Inverse Kinematics (FABRIK IK)

Как заставить ноги персонажа реалистично стоять на наклонной горе, а руки — хвататься за края блоков при паркуре? 
Вместо ручного подбора углов суставов используется **Инверсная Кинематика (IK)** на базе передового алгоритма **FABRIK** (Forward And Backward Reaching Inverse Kinematics).

```
   1. Исходное        2. Backward Pass (К цели)       3. Forward Pass (К базе)
     База               База                             База (Привязана!)
     O                   O                                O
      \                   \                                \
       \                   \                                \
        O                   O                                O
         \                   \                                \
          \ Target            \ Target (Сошлась!)             \ Target
           X                   O                               O
```

### 4.1 Алгоритм FABRIK
FABRIK не использует тяжелую тригонометрию и перемножение матриц Якобиана. Он работает **исключительно на геометрических операциях с векторами**, что делает его в 10 раз быстрее аналогов.

Дана цепочка костей: $p_0$ (плечо), $p_1$ (локоть), $p_2$ (кисть). Длины костей $d_1, d_2$. Цель $T$.

#### Шаг 1: Backward Pass (Обратный ход)
Мы принудительно перемещаем кисть $p_2$ в точку цели $T$:
$$p_2' = T$$
Затем находим новое положение локтя $p_1'$, сдвигая его по вектору от $p_2'$ к старому $p_1$ на фиксированную длину кости $d_2$:
$$\vec{v} = p_1 - p_2'$$
$$p_1' = p_2' + \text{Normalize}(\vec{v}) \times d_2$$
Повторяем операцию до плеча $p_0'$.

#### Шаг 2: Forward Pass (Прямой ход)
Так как плечо оторвалось от тела (базы), мы принудительно возвращаем его в исходную точку сустава $B$:
$$p_0'' = B$$
Затем двигаемся обратно к кисти, сдвигая кости на их фиксированные длины:
$$\vec{u} = p_1' - p_0''$$
$$p_1'' = p_0'' + \text{Normalize}(\vec{u}) \times d_1$$
Повторяем до кисти $p_2''$.

Оба шага повторяются 3-4 раза. Цепочка сходится с погрешностью менее 0.001 мм за микросекунды!

## 5. Подготовка к собеседованию (IT-Шпаргалка)

### Вопрос 1: В чем заключается проблема Gimbal Lock (шарнирного замка) при использовании углов Эйлера? Как кватернионы решают эту проблему?
*   **Ответ**: 
    *   **Gimbal Lock** возникает, когда при последовательном повороте объекта вокруг трех осей (например, по матрицам Yaw-Pitch-Roll) одна из осей вращения поворачивается на 90 градусов и совпадает с другой осью. В результате объект теряет одну степень свободы в трехмерном пространстве. Любые дальнейшие изменения углов приводят к резким скачкам модели и невозможности плавно повернуться в нужном направлении.
    *   **Решение кватернионов**: Кватернион представляет собой поворот сразу в четырехмерном пространстве вокруг одного произвольного единичного вектора (оси) на заданный угол. У него нет последовательных промежуточных осей, поэтому они физически не могут совпасть или заблокировать друг друга. Вращение с помощью кватернионов абсолютно гладкое во всех трех плоскостях.

### Вопрос 2: Объясните разницу между LERP (линейная интерполяция) и SLERP (сферическая интерполяция) при сглаживании 3D вращений. В каких случаях применяется каждый метод?
*   **Ответ**: 
    *   **LERP (Linear Interpolation)** выполняет интерполяцию компонентов вектора или кватерниона по прямой линии между двумя точками:
        $$\text{Lerp}(A, B, t) = A(1 - t) + Bt$$
        *Применение*: Используется для плавного перемещения позиций (Translation), так как прямая линия — это кратчайший путь в пространстве. В случае кватернионов LERP (или NLERP с последующей нормализацией) используется для быстрых, малоотличающихся вращений, так как он дешев в вычислениях.
    *   **SLERP (Spherical Linear Interpolation)** интерполирует кватернионы по дуге большого круга четырехмерной сферы с постоянной угловой скоростью:
        $$\text{Slerp}(q_1, q_2, t) = \frac{\sin((1-t)\theta)}{\sin\theta}q_1 + \frac{\sin(t\theta)}{\sin\theta}q_2$$
        *Применение*: Используется для интерполяции углов вращения костей скелета при больших углах. SLERP гарантирует отсутствие ускорений и замедлений в процессе вращения (угловая скорость абсолютно постоянна), предотвращая визуальные рывки суставов.

### Вопрос 3: Опишите математический принцип работы алгоритма FABRIK IK (Inverse Kinematics). Почему он предпочтительнее классических методов на основе матриц Якобиана?
*   **Ответ**: 
    *   **FABRIK** решает задачу инверсной кинематики итерационным геометрическим методом. Алгоритм не рассчитывает углы тригонометрически. Вместо этого он итеративно перемещает вершины суставов сначала с конца цепи к цели (Backward Pass), а затем от начала (базы) к концу (Forward Pass), проецируя точки на направления костей с сохранением их жестких длин.
    *   **Преимущества перед матрицами Якобиана**:
        1.  **Вычислительная сложность**: Якобиан требует построения больших матриц частных производных и их дорогого обращения ($O(N^3)$), что сильно нагружает CPU. FABRIK использует простейшие векторные сложения и деления, работая за линейное время ($O(N)$).
        2.  **Стабильность**: Якобиан страдает от сингулярностей (деление на ноль в экстремальных позах), из-за чего руки персонажей могут внезапно "взрываться" или улетать. FABRIK сходится стабильно при любых позах, даже если цель находится за пределами досягаемости конечности (в этом случае цепь просто вытягивается ровной линией в сторону цели).
