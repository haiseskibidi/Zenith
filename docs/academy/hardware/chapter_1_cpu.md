# Глава 1. Анатомия CPU: Такты, регистры и предсказание будущего

В предыдущей главе мы увидели, как миллионы микроскопических транзисторов КМОП объединяются в логические вентили и сумматоры, способные выполнять базовые математические операции над битами. Но как координировать эту гигантскую армию кремния? Кто заставляет их работать синхронно, превращая хаос электрических переключений в логику выполнения программы?

Этим дирижером является **Центральный Процессор (CPU)**. В этой главе мы препарируем процессорное ядро, заглянем внутрь его конвейеров, разберем физику тактовой частоты, логику спекулятивного выполнения команд и выясним, почему современный CPU — это не просто калькулятор, а сложнейший предсказатель будущего.

---

## 1. Ритм кремния: Тактовый генератор и физика частоты

Любой процессор работает в строгом ритме. Этот ритм задает **генератор тактовых импульсов** (Clock). Физически он представляет собой крошечную металлическую капсулу с кристаллом кварца внутри (кварцевый резонатор). Под действием электрического тока кварц начинает колебаться с фиксированной, эталонной частотой (обычно 100 МГц).

Специальная схема — **ФАПЧ (Фазовая автоподстройка частоты, или PLL - Phase-Locked Loop)** — умножает эту базовую частоту до гигагерцовых значений (например, умножитель x40 превращает 100 МГц в 4.0 ГГц).

```
   [ Кварцевый резонатор ] ────> [ Схема умножения PLL ] ────> [ Тактовая шина CPU ]
        (100 МГц)                   (Умножитель x40)               (4.0 ГГц)
                                                                       │
                                      ┌────────────────────────────────┴──┐
                                      ▼                                   ▼
                               [ Регистровый файл ]              [ Арифметические блоки ]
```

Что такое **процессорный такт (Clock Cycle)**? 
Это один период тактового сигнала — время между двумя последовательными импульсами генератора. При частоте 4.0 ГГц один такт длится всего **0.25 наносекунды** ($2.5 \cdot 10^{-10}$ секунды!). 
За один такт электрический сигнал на физическом уровне успевает пробежать по кремниевым дорожкам расстояние около 2-3 сантиметров и преодолеть несколько десятков слоев транзисторов. Тактовая частота — это физический предел скорости прохождения сигналов через логические вентили до того, как они стабилизируются в новое значение (0 или 1).

## 2. Архитектура ядра: Фон-Нейман против Гарварда

Исторически существовало две базовые концепции построения вычислительных систем:

1. **Архитектура фон Неймана**:
   Программа (инструкции) и данные хранятся в одной и той же оперативной памяти и передаются по одной общей шине. Это простая схема, но у нее есть фундаментальное «бутылочное горлышко» (Von Neumann Bottleneck): процессор не может одновременно читать инструкцию и читать/записывать данные из памяти. Ему приходится делать это последовательно.
2. **Гарвардская архитектура**:
   Память инструкций и память данных физически разделены. У процессора есть отдельные шины для команд и для данных, что позволяет читать следующую команду одновременно с обработкой данных текущей команды.

В современных CPU используется **гибридный подход**:
* На внешнем уровне (оперативная память RAM) процессор выглядит как система фон Неймана: у нас единые планки памяти и общие системные шины.
* На внутреннем уровне процессорного ядра (кэш-память L1) используется Гарвардская архитектура: кэш L1 жестко разделен на **L1i (Instruction Cache)** для кода и **L1d (Data Cache)** для данных, каждый со своими независимыми конвейерными шинами доступа.

## 3. Внутреннее устройство ядра CPU

Современное процессорное ядро состоит из трех основных блоков:

```
  ┌────────────────────────────────────────────────────────┐
  │ Ядро CPU                                               │
  │                                                        │
  │  ┌──────────────────────┐      ┌────────────────────┐  │
  │  │ Устройство управления │ ───> │ Регистровый файл   │  │
  │  │ (Control Unit)       │      │ (Registers)        │  │
  │  └──────────────────────┘      └─────────┬──────────┘  │
  │              │                           │             │
  │              ▼                           ▼             │
  │  ┌──────────────────────────────────────────────────┐  │
  │  │ Арифметико-логическое устройство (ALU / FPU)      │  │
  │  └──────────────────────────────────────────────────┘  │
  └────────────────────────────────────────────────────────┘
```

1. **Регистровый файл (Register File)**:
   Набор сверхбыстрых локальных ячеек памяти, расположенных физически на самом кристалле ядра в непосредственной близости от вычислительных блоков. Чтение и запись в регистры занимает **0 тактов** (происходит в рамках текущего такта вычисления).
   В архитектуре x86-64 доступно:
   * 16 регистров общего назначения (GPR: RAX, RBX, RCX, RDX, RSI, RDI, RSP, RBP, R8-R15) разрядностью 64 бита.
   * Специальные регистры: **RIP (Instruction Pointer)** — хранит адрес текущей инструкции; **RFLAGS** — хранит флаги состояния (переполнение, ноль, знак и т.д.); **RSP (Stack Pointer)** — указывает на вершину стека в памяти.
   * Векторные регистры (YMM/ZMM) шириной 256/512 бит для SIMD-инструкций.
2. **Арифметико-логическое устройство (АЛУ / ALU)**:
   «Вычислительный цех» ядра. Состоит из физических сумматоров, схем сдвига и побитовых логических вентилей. Обычно ядро содержит несколько специализированных АЛУ:
   * Целочисленные АЛУ (ALU) для работы с обычными числами и указателями.
   * Блоки с плавающей запятой (FPU - Floating Point Unit) для обработки вещественных чисел `float`/`double`.
   * Векторные исполнительные блоки (Vector Units) для массовых параллельных вычислений.
3. **Устройство управления (Control Unit / CU)**:
   «Мозг» ядра. Оно считывает команды из памяти, расшифровывает их логику и генерирует микрокоманды управления для регистров и исполнительных блоков АЛУ.

## 4. Цикл выполнения инструкции (Instruction Cycle)

Каждая команда, будь то простейшее сложение `ADD RAX, RBX` или сложная операция работы с памятью, проходит через 5 классических стадий исполнения:

1. **Fetch (Выборка)**:
   Устройство управления обращается к кэшу команд L1i по адресу, указанному в регистре `RIP`, считывает байты инструкции и инкрементирует `RIP` для подготовки к следующему шагу.
2. **Decode (Декодирование)**:
   Байты команды расшифровываются. Процессор понимает, какую операцию нужно выполнить (сложение, перенос, прыжок) и какие операнды (регистры или адреса памяти) в ней участвуют.
3. **Execute (Выполнение)**:
   Управляющие сигналы подаются на входы АЛУ. АЛУ производит физическое вычисление (например, складывает значения двух регистров).
4. **Memory Access (Доступ к памяти)**:
   Если инструкция работает с памятью (например, загружает данные `MOV RAX, [RSP]`), ядро обращается к кэшу данных L1d для чтения или записи. Если нет — эта стадия пропускается.
5. **Writeback (Обратная запись)**:
   Результат вычисления из АЛУ или прочитанные из памяти данные записываются в целевой регистр в регистровом файле.

## 5. Конвейеризация: Кремниевый конвейер Генри Форда

Если бы процессор выполнял каждую инструкцию последовательно от начала до конца, то на одну инструкцию уходило бы 5 тактов. При частоте 4 ГГц мы получали бы низкую реальную производительность.

Поэтому инженеры внедрили **конвейерную обработку (Pipelining)**. Идея аналогична автозаводу Генри Форда: вместо того чтобы один рабочий собирал машину целиком, сборка разбивается на посты. Как только первая машина сдвигается на стадию окраски, второй рабочий начинает собирать на первом посту следующую машину.

```
Такт:       |  1  |  2  |  3  |  4  |  5  |  6  |  7  |
Команда 1:  | Fetch | Dec | Exec| Mem | WB  |     |     |
Команда 2:  |       | Fetch | Dec | Exec| Mem | WB  |     |
Команда 3:  |       |       | Fetch | Dec | Exec| Mem | WB  |
```

В идеальном конвейере на каждом такте завершается выполнение **одной полной инструкции** (Instruction per Cycle, IPC = 1). 
В современных процессорах конвейеры стали суперскалярными (содержат несколько параллельных путей сборки) и глубокими (от 15 до 20+ стадий у x86 процессоров). Это позволяет достигать IPC > 3-4 при высоких тактовых частотах.

### Конфликты конвейера (Hazards)

Однако конвейер — крайне хрупкая структура. Как только возникает нештатная ситуация, конвейер «спотыкается». Эти ситуации называют конфликтами (hazards):

1. **Структурные конфликты (Structural Hazards)**:
   Возникают, когда два разных шага конвейера одновременно требуют один и тот же аппаратный ресурс (например, две инструкции одновременно пытаются прочитать данные из кэша L1d по одной шине).
   * *Решение*: дублирование аппаратных блоков или разделение кэшей L1 на порты чтения-записи.
2. **Конфликты по данным (Data Hazards)**:
   Возникают, когда выполнение инструкции зависит от результата предыдущей инструкции, которая еще не завершила свой путь по конвейеру.
   *Пример*:
   ```assembly
   ADD RAX, RBX  ; Результат запишется в RAX только на стадии Writeback (такт 5)
   SUB RCX, RAX  ; Требует значение RAX уже на стадии Decode (такт 3!)
   ```
   Если ничего не предпринять, вторая команда считает старое «грязное» значение `RAX`.
   * *Решения*:
     * **Пузыри конвейера (Stalls / Bubbles)**: Аппаратный контроллер приостанавливает декодирование второй инструкции, вставляя «холостые такты» (пузыри), пока первая инструкция не запишет результат в регистр. Это снижает IPC.
     * **Обход данных (Forwarding / Bypassing)**: Инженеры создают дополнительные физические дорожки от выхода АЛУ напрямую к его входу. Новое значение `RAX` пробрасывается во вторую команду сразу после стадии Execute первой команды, минуя стадию Writeback. Конвейер не простаивает!
3. **Конфликты управления (Control Hazards)**:
   Самый страшный враг конвейера — **ветвление** (инструкции условных переходов `JZ`, `JNZ` и т.д.).
   Когда процессор декодирует условный переход, он физически не знает, по какому адресу считывать следующую инструкцию (`Fetch`), пока текущее условие перехода не выполнится в АЛУ на стадии `Execute`. 
   Если остановить конвейер и ждать вычисления условия, мы потеряем 15-20 тактов простого простоя. Это катастрофический удар по производительности игр.

## 6. Предсказание будущего: Branch Predictor и спекулятивное выполнение

Чтобы конвейер не простаивал на ветвлениях, в процессоры встроен сложнейший аппаратный блок — **Предсказатель переходов (Branch Predictor)**.

Представь его как продвинутый статистический анализатор (иногда на базе аппаратных перцептронов / нейросетей), который ведет учет истории всех переходов. Когда процессор видит условный переход, он делает ставку: «условие выполнится» или «условие не выполнится».

```
                            [ Условный переход ]
                                     │
                    ┌────────────────┴────────────────┐
                    ▼                                 ▼
         [ Ставка: Переход БУДЕТ ]        [ Ставка: Перехода НЕ БУДЕТ ]
         Продолжаем конвейер по           Продолжаем конвейер по
         адресу перехода (спекулятивно)    линейному коду (спекулятивно)
                    │                                 │
                    └────────────────┬────────────────┘
                                     ▼
                      [ АЛУ вычисляет реальное условие ]
                                     │
            ┌────────────────────────┴────────────────────────┐
            ▼                                                 ▼
     [ Угадали! ]                                     [ Ошибка предсказания! ]
   IPC на максимуме,                                  Штраф: сброс конвейера,
   спекулятивные результаты                           удаление микроопераций,
   становятся реальными.                              откат регистров. Потеря 15-20 тактов.
```

### Спекулятивное выполнение (Speculative Execution)

Сделав ставку, процессор не просто ждет. Он начинает загружать и выполнять инструкции по предсказанному пути **спекулятивно** (в долг). 
Все результаты расчетов записываются не в реальные регистры общего назначения, а во временные буферы — **ROB (Reorder Buffer / Буфер переупорядочивания)**.

* **Если предсказание сбылось**:
  Все спекулятивные результаты из ROB мгновенно переносятся в реальные регистры процессора. Это называется **фиксированием результатов** (Commit). Процессор пролетает развилку на полной скорости, не потеряв ни одного такта!
* **Если предсказание оказалось ошибочным (Branch Misprediction)**:
  Происходит аварийная остановка. Все спекулятивно вычисленные инструкции в конвейере и в ROB объявляются недействительными и уничтожаются. Процессор откатывает состояние регистров назад, очищает конвейер и начинает медленную загрузку кода с правильной ветки. 
  Этот штраф (Branch Misprediction Penalty) обходится в **15-20 потерянных тактов**!

> [!TIP]
> **Пример из геймдева (сортировка данных)**:
> Представь цикл, обрабатывающий миллионы объектов: `if (object.isActive) { process(object); }`. Если массив объектов расположен в памяти хаотично, предсказатель переходов будет постоянно ошибаться, превращая FPS в слайд-шоу. Если же сначала отсортировать объекты так, чтобы сначала шли все активные, а затем неактивные, предсказатель быстро поймет паттерн («активный, активный... теперь все неактивные») и выдаст идеальную производительность с нулевым штрафом переходов.

## 7. Внеочередное выполнение (Out-of-Order Execution, OoO)

Классические процессоры выполняли код строго по порядку (In-Order). Если инструкция 1 зависала в ожидании данных из медленной RAM, то инструкции 2, 3 и 4, которым RAM не нужна, послушно стояли и ждали своей очереди.

Современные ядра x86 работают по принципу **внеочередного выполнения (Out-of-Order)**. Специальный блок планировщика (Scheduler) постоянно сканирует окно из сотен инструкций вперед. Если он видит, что Инструкция 1 зависла, но Инструкция 2 и 3 готовы к выполнению прямо сейчас, он отправляет их на свободные АЛУ вне очереди.

Для обеспечения этой магии используется технология **переименования регистров (Register Renaming)**. Физических регистров на кристалле ядра гораздо больше (например, 180 физических регистров), чем логических регистров x86 (16 регистров). Специальная таблица трансляции **RAT (Register Alias Table)** сопоставляет логические регистры (`RAX`, `RBX`) со свободными физическими регистрами «на лету», устраняя ложные зависимости по данным между независимыми кусками кода.

## 8. CISC против RISC: Микрооперации ($\mu\text{ops}$)

Исторически процессоры разделились на два лагеря:
* **CISC (Complex Instruction Set Computer)**, пример — x86. Инструкции имеют переменную длину, могут выполнять сложные действия за раз (например, считать из памяти, сложить с регистром и записать обратно одной командой). Это упрощает написание ассемблера, но аппаратно реализовать конвейер для таких инструкций-монстров невероятно сложно.
* **RISC (Reduced Instruction Set Computer)**, пример — ARM, RISC-V. Инструкции имеют фиксированный размер, простые, выполняются за 1 такт. Все операции с памятью делаются только через явные команды загрузки/выгрузки (`Load`/`Store`). На таком базисе строить быстрые конвейеры — одно удовольствие.

Современные процессоры Intel и AMD нашли компромисс. Снаружи они остаются **CISC** (чтобы сохранять совместимость со старым софтом x86), но на входе их конвейера стоит мощный блок **декодеров**. Он на лету «нарезает» сложные инструкции x86 на простые, элегантные внутренние RISC-подобные команды, которые называются **микрооперациями ($\mu\text{ops}$)**. Именно эти микрооперации крутятся в сверхбыстром внеочередном конвейере ядра.

## 9. Векторные вычисления: SIMD (AVX)

Обычные команды работают по принципу **SISD (Single Instruction Single Data)**: одна команда оперирует одной парой чисел.

При обработке графики, расчете физики или генерации чанков воксельного движка нам постоянно приходится выполнять одинаковые математические операции над огромными массивами данных (например, умножать 3D-вектора вершин на матрицы проекций).

Для этого в CPU встроены расширения **SIMD (Single Instruction Multiple Data)** — технологии SSE, AVX2, AVX-512. Они добавляют в процессор сверхширокие регистры (до 512 бит) и специальные АЛУ.

```
Обычное сложение float (SISD):
  A [ float 1 ]  +  B [ float 1 ]  =  [ A1 + B1 ]  (Один такт)

Векторное сложение AVX-512 (SIMD):
  A [ fl8 | fl7 | fl6 | fl5 | fl4 | fl3 | fl2 | fl1 ] 512 бит
                      +
  B [ fl8 | fl7 | fl6 | fl5 | fl4 | fl3 | fl2 | fl1 ] 512 бит
                      =
  Y [ A8+B8 | A7+B7 | A6+B6 | A5+B5 | A4+B4 | A3+B3 | A2+B2 | A1+B1 ] (Один такт!)
```

Используя AVX-512, процессор за одну инструкцию может сложить 16 чисел типа `float` (или 8 чисел `double`) параллельно! В 3D-движках это дает колоссальный прирост производительности при расчете физики частиц, скелетной анимации и трассировки лучей.

## 10. Бесшовный мост: Стена памяти (Memory Wall)

Мы создали шедевр инженерной мысли. Арифметико-логические устройства нашего CPU перемалывают математические и логические инструкции с безумной скоростью — за доли наносекунды. Конвейеры загружены микрооперациями, планировщики раскидывают задачи, а предсказатели переходов прокладывают путь сквозь ветвления.

Но вся эта кремниевая магия разбивается о жесткую физическую реальность.

АЛУ работает исключительно с регистрами. Но данные для регистров лежат в оперативной памяти (RAM). Физически чипы оперативной памяти находятся на расстоянии 5-10 сантиметров от процессорного сокета на материнской плате. Сигналу нужно пройти проводники, контроллер памяти, шины.

Для процессора, работающего на частоте 4 ГГц, один поход в оперативную память длится вечность — от **200 до 400 тактов простого ожидания**! 

Пока данные летят из RAM, сверхбыстрые АЛУ процессора просто стоят на месте, умирая от скуки. Этот феномен отставания скорости памяти от скорости ядер называют **стеной памяти** (Memory Wall). Чтобы спасти процессор от постоянной комы ожидания, инженеры окружили его ядра каскадом сверхбыстрой, локальной промежуточной памяти. Имя этому спасению — **иерархия кэшей**.
